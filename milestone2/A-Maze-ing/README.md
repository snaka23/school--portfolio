# A-Maze-ing: 柔軟な迷路自動生成・解析エンジン

## 1. 概要 (Description)
**A-Maze-ing** は、設定ファイル（`config.txt`）の記述に基づいて迷路を自動生成し、最短経路の解析やファイル出力を行うPythonアプリです。

正解ルートが1つだけの「完全迷路（Perfect Maze）」と、複数の迂回路が存在する「遊べる迷路（Playable Maze）」の2種類に対応しています。さらに、盤面上に「42」の文字パターンを自然に埋め込む機能や、スタートからゴールまでの最短解法ルート（BFS探索）の自動計算機能を備えています。

本プロジェクトの目的は、クリーンな設計思想（モジュール化）と厳密なアルゴリズム選定に基づき、拡張性と頑健性の高い迷路エンジンをゼロから構築することです。



## 2. 使用方法 (Instructions)

### 動作要件 (Prerequisites)
- Python 3.10 以上
- `make` ユーティリティ

### 実行コマンド

```bash
# 1. 依存ツールのインストール (flake8 / mypy / build)
make install

# 2. デフォルト設定で迷路を生成・実行
make run

# 3. pdbによるデバッグ実行
make debug

# 4. コードスタイルおよび型チェック (flake8 & mypy)
make lint

# 5. 一時ビルドファイルの削除
make clean
```

### インタラクティブ操作メニュー
アプリ起動後、ターミナル上に迷路が表示され、キーボード入力で以下の操作が可能です。

- 1.迷路を再生成する: シード値を更新して新しい迷路を生成（※出力テキストファイルも同時に自動上書き保存されます）。

- 2.最短経路の表示切り替え: BFSで計算された解法ルート（色付きライン）の表示 ON / OFF。

- 3.壁の色を変更する: ANSIカラーによる壁の表示色変更。

- 4.『42』パターンの強調色切り替え: 盤面中央の「42」文字パターンの強調表示 ON / OFF。

- 5.テーマ/フォント変更 [Bonus]: 記号や壁デザインのカスタマイズ。

- 6.プレイヤー操作モード [Bonus]: キーボードで迷路を実際にプレイするモード。

- 7.終了: アプリを終了。

## 3. 設定ファイルの構造 (config.txt)
設定ファイルは KEY=VALUE の形式で記述します。# から始まる行および空行はコメントとして無視されます。
### 1. 設定ファイル構造
```Plaintext
| ------------------------------------------------------------
| a-maze-ing 構造化設定ファイル (config.txt)                      
 -------------------------------------------------------------

# 【基本サイズ設定】 --------------------------------------------
WIDTH=20             <-- [必須] 盤面の横幅 (1以上の整数)
HEIGHT=15            <-- [必須] 盤面の高さ (1以上の整数)

# 【スタート・ゴール座標】 ---------------------------------------
ENTRY=0,0            <-- [必須] 入口座標 "X,Y" (左上 = 0,0)
EXIT=19,14           <-- [必須] 出口座標 "X,Y" (右下 = WIDTH-1, HEIGHT-1)

# 【ファイル出力・ルール設定】 -----------------------------------
OUTPUT_FILE=maze.txt <-- [必須] 生成結果の保存パス
PERFECT=True         <-- [必須] True : 正解1本 (一本道)
                     #          False: ループあり (遊べる迷路)

# 【オプション拡張設定】 ----------------------------------------
SEED=42              <-- [任意] 乱数シード (指定すると同じ迷路を再現)
```
### 2. 座標系と盤面イメージ図
ENTRY・EXIT・WIDTH・HEIGHT が実際にどのようなグリッド（格子）に対応しているかの概念図です。
```Plaintext
(横幅: WIDTH = 20 セル)
      x=0   x=1   x=2  ...  x=18  x=19
    +-----+-----+-----+----+-----+-----+
y=0 |  Ｓ |     |     |    |     |     |  <-- ENTRY=0,0 (スタート)
    +-----+-----+-----+----+-----+-----+
y=1 |     |     |  4  |  2 |     |     |  <-- "42" パターン埋め込み領域
    +-----+-----+-----+----+-----+-----+      (自動計算で中央付近に配置)
y=2 |     |     |     |    |     |     |
    +-----+-----+-----+----+-----+-----+
 :  |  :  |  :  |  :  |  : |  :  |  :  |
    +-----+-----+-----+----+-----+-----+
y=14|     |     |     |    |     |  Ｇ |  <-- EXIT=19,14 (ゴール)
    +-----+-----+-----+----+-----+-----+
      (高さ: HEIGHT = 15 セル)
```

### 3. 設定値から迷路生成フローへのデータ流れ図
config.txt の内容がどのようにプログラムに読み込まれ、処理されるかのフロー図です。
```Plaintext
[ config.txt ]

       ▼
┌─────────────────────────┐
│  Config Parser          │  ・コメント行 (#) と空行を除外
│  (config.py)            │  ・構文チェック & 型変換 (int, bool, tuple)
└────────────┬────────────┘
             │
             ▼ 妥当性チェック (Validation)
             ├─ ENTRY / EXIT が盤面内にあるか？ (0 <= x < WIDTH)
             └─ 数値が正の整数か？
             │
             ▼ データ構造化 (Dict / Dataclass)
┌─────────────────────────┐
│  MazeGenerator          │  ・PERFECT=True  ──> Iterative Backtracker
│  (mazegen/maze.py)      │  ・PERFECT=False ──> Braiding (壁破壊)

             │

┌─────────────────────────┐
│  maze.txt               │  ・セル状態 (0〜Fの16進数)
│  (ファイル出力)           │  ・ENTRY / EXIT / 最短ルート (フッター)
└─────────────────────────┘
```

## 4. 迷路生成・解法アルゴリズム (Maze Generation & Solving Algorithms)
### 1. 完全迷路 (PERFECT=True)
採用アルゴリズム: 非再帰版バックトラッカー（明示的スタックを用いた深さ優先探索）

仕組み: 暗闇の中で壁を突き進んで掘り進み、行き止まりになったら「ひとつ前の分かれ道」まで戻って別の方向を掘り進める穴掘り法と呼ばれるものです。

選定理由: 構造が単純でありながら、スタートからゴールまでの正解ルートが厳密に1つだけ存在する完全迷路（単一全域木）を確実に生成できます。Pythonのデフォルト再帰上限によるスタックオーバーフローを防ぐため、システム再帰ではなく明示的なリスト（Stack）を用いた反復処理で実装しており、超大型迷路でも安定して生成可能です。

### 2. 遊べる迷路 (PERFECT=False)
採用アルゴリズム: 空間バリデーション付き自作編み込み（Braiding）アルゴリズム

仕組み: まず「完全迷路」を構築した後、行き止まり（Dead-end）の壁を選択的に破壊して環状経路（ループ）や迂回路を作り出します。

選定理由: 一本道だけの迷路よりも複数のルート選択が存在する方がゲームとして遊んだ際に面白いためです。単に壁をランダム破壊するのではなく「周囲3×3マスが完全な空洞（広場）にならないか」を判定する安全装置を組み込み、行き止まりを全消去(42パターンを除く)した（Dead-end free）プレイしやすい盤面を実現しています。

### 3. 「42」パターンの埋め込み
採用方式: 事前領域予約方式（Pre-generation Reservation）

仕組み: 迷路の通路を掘り始める前に、「42」の文字の形をなすセルを「訪問不可（壁）」としてあらかじめ予約・隔離します。

選定理由: 迷路が出来上がった後に壁をくり抜くと通路の連結性が分断される危険があります。生成前に領域を予約しておくことで、バックトラッカーが文字の周囲を自然に回り込むように道を掘るため、グラフの連結性を破綻させずにパターンを配置できます。

### 4. 最短経路探索 (solve())
採用アルゴリズム: 幅優先探索（BFS）

仕組み: entryから、壁の開いている隣接セルだけを辿りながら、「entryからの距離が近い順」にキューへ積んでいきます（先入れ先出し）。exitに到達した時点で探索を打ち切り、たどってきた経路を逆順に復元して N/E/S/W の移動指示列に変換します。

選定理由: 迷路は各通路の移動コストがすべて等しい（重み無し）グラフです。BFSは「entryからの距離が近い順」に層状に探索が広がる性質があるため、exitに最初に到達した経路が必然的に最短経路になります。この単純な性質だけで最短迷路を保証できるため、実装もシンプルに済みます。

## 5. 出力ファイルのフォーマット (maze.txt)
出力されるテキストファイルは、各セルの壁の状態を1桁の16進数文字（`0`〜`F`）で表現し、最下部にメタ情報（フッター）が付与されます。

### 16進数（ビットフィールド）による壁の表現
各セルは 4 ビットで東西南北の壁の有無（`1` = 壁あり, `0` = 壁なし）を表します。
```Markdown
- **Bit 0 (1):** 北 (North)
- **Bit 1 (2):** 東 (East)
- **Bit 2 (4):** 南 (South)
- **Bit 3 (8):** 西 (West)

(例: `F` (1111) = 全方位が壁 / `0` (0000) = 全方位が通路 / `C` (1100) = 南と西が壁)

フッター情報（末尾3行）:

スタート位置（例: 0,0）

ゴール位置（例: 19,14）

最短解法ルートの移動指示（例: EESSSW... ※ N=北, E=東, S=南, W=西）
```
### ファイル構造例
```
9C689C6
39A2312
6A6C6A4  <-- ここまで各マスの「壁の状態」を表す16進数データ
3A2A2A1
------------（ファイルの最下部：ここからがフッター情報）------------
0,0      <-- 1行目: スタート地点（ENTRY）の座標 (x,y)
19,14    <-- 2行目: ゴール地点（EXIT）の座標 (x,y)
EESSSWEE <-- 3行目: スタートからゴールまでの「最短解法ルート」
```


## 6. 再利用可能なコンポーネント (mazegen)
迷路生成・解析のコアロジックは、独立した Python パッケージ `mazegen` として設計されています。

プロジェクトルートにある `pyproject.toml` (または `setup.py`) により、CLIツールやUI表示機能（`display/`）から完全に分離されており、独立して他のプロジェクトへ組み込むことが可能です。

#### 使用コード例 (Example Code)
```Python
from mazegen.maze import MazeGenerator, MazeGeneratorError

try:
    # 1. ジェネレータの初期化
    generator = MazeGenerator(
        width=20,
        height=15,
        entry=(0, 0),
        exit=(19, 14),
        perfect=True,
        seed=42
    )

    # 2. 迷路盤面の生成
    maze = generator.generate()

    # 3. 幅優先探索（BFS）による最短経路の算出
    shortest_path = maze.solve()
    print("最短手順:", shortest_path)

except MazeGeneratorError as e:
    print(f"迷路生成エラー: {e}")
```
実装側の補足（mazegen/__init__.py の書き方）:

上記の記述に対応するため、mazegen/__init__.py には以下の通り公開インターフェースを定義しています。

```Python
from .maze import MazeGenerator, MazeGeneratorError

__all__ = ["MazeGenerator", "MazeGeneratorError"]
```
